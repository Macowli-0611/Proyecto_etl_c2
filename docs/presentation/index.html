Calcula el ratio de casos_por_comisaria = denuncias_totales / comisarias_activas. Permite detectar municipios donde cada comisaría atiende más de 1,000 incidentes al año (ej. Soacha, Cali, Medellín).

Ingeniería & Pipeline

Arquitectura del Sistema y Flujo End-to-End

Diseño dual-branch con compuertas de calidad no bloqueantes a nivel profiling y compuertas críticas atómicas.
Sección 7
🔍 Clic para ampliar
Decisiones Clave de Arquitectura
  • Desacoplamiento Estricto: Se separa el profiling de la transformación, y la validación de la limpieza (Sección 10).
  • Arquitectura Dual-Branch: Ambas ramas (primaria y API) se extraen y validan en paralelo antes de confluir en la integración.
  • Inmutabilidad de Raw: Los datos crudos se preservan intactos junto con sus manifiestos criptográficos (SHA-256).
  • Task Interfaces Ligeras: Se evita usar XCom para mover datos masivos; solo transfiere metadatos (`batch_id`, paths parquet, métricas).
  • Carga Atómica: PostgreSQL ejecuta la carga de 6 tablas y vistas analíticas dentro de una sola transacción ACID.

Ingeniería de Transformación

Contrato de Integración y Deduplicación al Grano

Tratamiento de llaves dispares, reconciliación geográfica y deduplicación con conservación exacta de métricas.
Sección 13
Contrato de Integración Geográfica DANE 5 Dígitos
Estrategia para resolver discrepancias entre catálogo policial y directorio judicial.
  • Normalización de Clave: Relleno a 5 dígitos (zfill(5)) para eliminar desajustes entre "5001" y "05001" (Medellín).
  • Tratamiento de Nombres: Limpieza y estandarización a Title-Case para eliminar discrepancias de tildes y mayúsculas.
  • Manejo de Casos de Borde (2 Municipios Especiales): El directorio API reporta 2 municipios con comisarías pero 0 denuncias policiales registradas. Se preservan en dim_geografia con sus métricas institucionales sin generar claves huérfanas.
  • Enriquecimiento Institucional: Se computan las columnas de soporte total_comisarias y tiene_comisaria en la dimensión geográfica.

Ingeniería Crítica & Futuro

Limitaciones Técnicas y Estrategia de Escalabilidad

Evaluación objetiva de restricciones operacionales del dominio y evolución hacia arquitecturas distribuidas.
Secciones 24 y 27
Limitaciones del Dominio y del Pipeline Análisis Crítico
  • Subregistro Estadístico (Cifra Negra): Los datos representan únicamente denuncias formales ante la Policía Nacional. No capturan agresiones no reportadas por miedo, dependencia o inaccesibilidad física.
  • Desfase Temporal del Directorio API: El catálogo de comisarías del MinJusticia se actualiza semestralmente; cambios recientes en sedes pueden tardar en verse reflejados.
  • Escalamiento Vertical de PostgreSQL: Para cargas superiores a 10M de registros, el bulk copy requiere particionamiento temporal y ajuste de maintenance_work_mem.
Hoja de Ruta de Escalabilidad (Cloud Native) Roadmap
  • Streaming Ingestion: Evolución de ingesta batch hacia Apache Kafka para procesar alertas en tiempo real desde comisarías conectadas.
  • Data Lakehouse Modular: Almacenamiento en capas Bronze/Silver/Gold sobre formato Apache Iceberg / Delta Lake en Amazon S3.
  • Orquestación en Kubernetes: Despliegue de ejecutores distribuidos (Celery/KubernetesExecutor) en Airflow para paralelismo masivo de tareas de profiling.
  • CI/CD DataOps: Automatización de pruebas GX previas a producción mediante GitHub Actions.
